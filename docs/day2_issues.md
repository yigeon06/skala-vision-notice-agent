# 2일차 문제 기록

2026-10-21 — 이후 발생하는 문제는 이 문서에 번호를 이어서 추가한다.

## 1. 2일차 목표와 검색 구조

- 공지·일정 질문을 SQL 조건 검색과 벡터/RAG 의미 검색으로 처리한다.
- 답변을 뒷받침하는 공지만 출처로 표시한다.

## 2. 근거가 없는 공지가 검색 결과로 표시되는 문제

- 질문: “항공회사 지원 시 필요한 자격증은 어떤 게 필요해?”
- 자격증 정보가 없는 `Procurement 경력사원 채용`이 유사도 0.491로 반환됐다.
- 답변은 “확인할 수 없다”고 하면서 관련 없는 출처 카드를 표시했다.

## 3. 원인

- 벡터 검색은 정답 유무와 관계없이 가까운 상위 청크를 반환한다.
- 기존 RAG는 답변 근거 확인 없이 상위 공지를 출처로 사용했다.
- 유사도 점수만으로 답변 가능 여부를 판단하지 않았다.

## 4. 해결 과정

- RAG 응답을 `supported`, `answer`, `source_notice_ids` Structured Outputs로 변경했다.
- 질문의 조건이 공지에 명시된 경우만 `supported=true`로 처리하고, 실제 답변에 사용한 공지만 출처로 반환한다.
- 근거가 없으면 고정 안내를 표시하고 출처를 비운다.

## 5. 검증 방법

- 관련 공지가 있는 질문, 없는 질문, 모델이 존재하지 않는 공지 ID를 반환하는 경우를 확인한다.
- 2026-10-21 사용자 승인에 따라 전체 모의·회귀 테스트를 실행했다. `.venv/bin/python -m pytest tests -q` 결과 RAG 근거 판정 테스트를 포함해 56개가 통과했다. 실제 모델을 이용한 질문 평가는 아직 실행하지 않았다.

## 6. 남은 한계

- 의미 질문이 조건 없는 SQL 검색으로 잘못 분류될 수 있다. 이번 수정에는 분류 로직 변경을 포함하지 않았다.
- 실제 질문 평가 후 유사도 임계값을 검토해야 한다.

## 7. 실제 모델 점검에서 신청 마감 유형 오분류 발견 — 2026-10-21

- 기존 샘플 생성기의 정보보안 교육 공지 1장을 임시 DB에 등록해 실제 Qwen OCR·GPT 구조화·bge-m3 임베딩·검색을 실행했다.
- OCR에 ‘신청 마감: 2026년 10월 23일까지’가 있었지만 구조화 결과는 `submission_deadline`이었다. 날짜 자체는 맞았다.
- ‘이번 주 신청 마감인 공지를 찾아줘’는 서울 기준 10월 19일 이상·26일 미만, `application_deadline` 조건으로 정상 해석됐지만 저장된 유형이 달라 빈 결과를 반환했다.
- 현재 필수값 검증은 유형의 의미 불일치를 검사하지 않아 `confirmed`가 됐고, 재구조화는 실행되지 않았다. 이 실행에서 재시도 분기의 실제 모델 동작까지 확인한 것은 아니다.
- 등록·임베딩 생성·동일 요청 중복 방지·신청 방법 답변과 출처·없는 자격증 질문의 근거 없음 처리는 통과했다.
- 원문과 일정 유형의 불일치 검증 및 재구조화 대상 확장은 별도 계획 승인 후 진행한다. 현재는 문제를 기록했으며 동작 코드를 추가 수정하지 않았다.

## 8. 일정 유형 오분류 보완 및 재검증 — 2026-10-21

- 원문의 명확한 마감 표현과 `event_type`의 충돌을 검증하도록 보완했다. 신청·지원·모집·예약 마감과 서류·자료·비용·영수증 제출 마감을 구분한다.
- 양쪽 의미가 함께 있거나 표현이 애매하면 규칙으로 유형을 결정하지 않는다. 충돌은 값을 직접 교정하지 않고 기존 구조화 최대 1회 재시도에 연결하며, 미해결 시 `needs_review`로 반환한다.
- 관련 테스트를 추가한 뒤 전체 모의·회귀 테스트 60개가 통과했다.
- 새로운 임시 DB에서 동일 생성 공지를 실제 모델로 재검증했다. `application_deadline` 저장과 이번 주 신청 마감 조회를 포함한 10개 확인 항목이 모두 통과했다.
- 재검증에서는 최초 구조화 결과가 올바르게 나와 실제 모델의 재시도 분기는 실행되지 않았다. 해당 분기는 모의 테스트로 성공·미해결·호출 실패를 검증했다.
